# 第 4 件事：让 Codex 搭建美国网络

目标：**电脑 → ClashFX → 自己的美国 VPS → 自己购买的美国静态住宅 IP**。

## 你要做什么

确认前面两项购买已开通，告诉 Codex 服务器和住宅资料的私有文件位置。需要登录或系统授权时本人完成；其余操作交给 Codex。

## 给 Codex 的部署步骤

1. **检查与备份。** 检查 SSH 管理权限、系统、端口、防火墙与已有服务，先备份相关配置，复用现有服务器和客户端。
2. **测试住宅上游。** 在美国 VPS 用商家实际协议和认证连接代理网关，连续检测结果等于购买的固定出口。主机字段填商家接入主机，不填住宅出口 IP。
3. **部署服务器。** 安装或复用 [3X-UI / Xray](https://github.com/MHSanaei/3x-ui)。管理面板私有访问；建立兼容客户端的 SS2022 / Reality 加密入站和美国住宅出站，将每个入站明确路由到同一个住宅出站。HTTP CONNECT 上游支持 TLS 时验证证书；配置按实际软件版本校验，保存到持久配置。
4. **配置电脑。** 生成并导入本人节点。界面只有“美国住宅出口”一个公网组，最终公网规则指向它；如有备用协议，也必须验证是同一住宅出口。配置系统代理和增强模式，处理代理核心、VPS 接入、DNS 与局域网例外，避免重复代理。维护已有 NAS、远程连接与本机服务。
5. **核对真实应用。** 检查 Claude Code 或桌面端的实际进程、API 地址和请求链，必要时在应用自身设置代理。普通浏览器和需要的应用都使用美国住宅出口，不只测一个网页。
6. **匹配电脑时区。** 查询实际美国住宅出口对应的地区和时区，结合商家资料核实；信息冲突时先确认。记录电脑原时区，再将系统时区设置为住宅出口的时区。美国有多个时区，按住宅出口确定，不能按 VPS 机房猜测。关闭基于电脑当前位置的自动时区，保留自动对时与该地区的夏令时规则。需要管理员验证时，由本人在系统界面完成；修改后重新读取系统时区确认生效，记录恢复原设置的方法。
7. **检查持久化。** 重启服务和客户端后复测。检查公网 IPv6 与代理断开后的行为；额外系统防护需要本人授权和独立实测，未完成时如实报告。
8. **交接。** 保存不含秘密的部署进度、使用方法、验收与回滚说明。若用户需要 AdsPower，继续 [第 5 步](05_安装和配置AdsPower_可选.md)；否则直接做 [第 6 步验收](06_检查网络与日常使用.md)。

## 执行要求

从官方来源获取软件，按实际版本适配。若使用 Reality，目标和 SNI 必须从自己的 VPS 验证，原案例使用 `icloud.com`；不需要为此托管网站。

时区示例：旧金山住宅出口使用太平洋时区，Mac 对应 `America/Los_Angeles`，Windows 对应 `Pacific Standard Time`。其他地区按实际出口核实，使用地区时区规则处理夏令时。[Mac 时区设置](https://support.apple.com/zh-cn/guide/mac-help/mchlp1124/mac) · [Windows 时区说明](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/default-time-zones?view=windows-11)

局域网与连接 VPS 本身是接入例外，不作为业务公网备用出口。住宅上游不支持的协议应明确处理，不能悄悄改为公网直连。

账号、密码、密钥、订阅和节点链接保存到本人独立私有位置，不写回这套分享文档。不要重装已可用的 VPS，不覆盖原有网站。遇到确实需要本人操作的步骤，给出一个明确动作，完成后继续。

“面板运行”“节点导入”和无认证接口返回 401 只能证明部分结果；完成标准以第 6 步的实际验收为准。
