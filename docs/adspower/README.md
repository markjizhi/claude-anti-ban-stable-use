# 让 Codex 帮你配置 AdsPower 指纹浏览器

极致先生 · 2026-10-17

配套的网络搭建步骤见 [美国 VPS＋静态住宅 IP 教程](../us-residential-network/README.md)。

把这份文档交给你电脑上的 Codex，让它帮你安装 AdsPower、配置代理和时区，并打开真实浏览器验证结果。你负责自己的账号登录、验证码和系统要求的本人验证。

配置后的网络路径是：**AdsPower 浏览器 → 你的美国 VPS → 你的美国静态住宅 IP**。

适用前提：你已经有自己的美国 VPS 和美国静态住宅代理。VPS 上还没有浏览器专用入口时，Codex 需要先补上这个入口。只有 ClashFX 节点链接，还不能直接填进 AdsPower。

## 你只需要做这三步

1. 把本文件保存到电脑，用本机 Codex 打开，或作为文件发给它。
2. 复制下面的启动话术给 Codex。
3. 按提示完成登录、提供你自己的连接资料和系统验证。每次只处理 Codex 提出的下一步。

Codex 需要能够访问本机文件、终端及相关应用。有浏览器或桌面操作工具时可以协助操作；缺少操作能力时，让它明确告诉你当前需要点哪个按钮。

## 以下步骤由 Codex 执行

### 第一步 检查安装和必要资料

检查电脑系统、AdsPower 安装与登录状态。未安装时，从 [AdsPower 官方下载页](https://www.adspower.net/download) 选择适合电脑的正式版；已安装可用版本就复用。账号由本人注册或登录。

确认以下资料是否齐全，只询问缺少的部分：

| 资料 | 用途 |
|---|---|
| 美国 VPS 的 SSH 地址、端口、登录方式和管理权限 | 检查或建立浏览器代理入口 |
| 美国住宅代理的网关、端口、账号、密码和预期固定出口 | 检查 VPS 的最终出站 |
| 已有 VPS 代理入口的地址、端口和专用认证（如果有） | 直接用于浏览器配置 |

三套资料要分清：AdsPower 账号用于登录软件；VPS 代理账号用于连接浏览器入口；住宅代理账号用于 VPS 连接住宅服务商。VPS 网站登录密码也不能当作 SSH 或代理密码。

### 第二步 准备 VPS 的 HTTPS 代理入口

已有可用入口时直接检查和复用；只有 SS2022、Reality 等客户端节点时，需要另外建立 AdsPower 能连接的 HTTPS 代理入口。

先备份相关配置，在同一美国 VPS 上配置：**有认证的 HTTPS 入口 → 已验证的美国住宅出站**。可使用 TLS 前端加仅监听服务器回环的认证 HTTP 后端，或当前软件支持的等效实现。使用匹配主机名或地址的可信证书，安排证书续期，并确认来源访问限制适合本人网络。保留已有服务与端口。

从 VPS 发起请求，确认最终出口与本人购买的住宅出口一致；再从电脑验证 HTTPS 代理入口的认证、证书和网络连通性。主机字段是 VPS 入口，住宅出口只用于核对结果。

本方案要求电脑能直接连到 VPS 的该入口。若必须经过其他本地代理才能连接，先说明这个条件尚未满足，不要把绕经 ClashFX 的结果当成独立直连成功。若使用 TUN，检查 VPS 接入连接的例外规则，避免重复代理。

### 第三步 选择配置方式

优先使用已经可用的 AdsPower Local API 或现有操作工具。先检查本人账号权限和接口状态，按 [官方 Local API 文档](https://localapi-doc-en.adspower.com/docs/Rdw7Iu) 适配当前版本。需要操作工具时，可参考 [AdsPower 官方工具说明](https://github.com/AdsPower/adspower-browser)。API Key 仅保存在本人私有配置中，本地控制接口只允许本机访问。

没有 API 权限时，使用可用的桌面操作工具配置；没有桌面操作工具时，给本人当前界面的准确操作步骤。不要为使用 API 默认购买套餐，也不要把“API 可以创建环境”当成已经控制了浏览器页面。

### 第四步 配置浏览器环境

有本人明确指定的环境就先备份并修改它；没有时，新建一个名为“美国住宅日常使用”的环境。不要删除其他环境或清理既有登录数据。选择当前电脑上可用的浏览器内核，操作系统和浏览器版本设置保持匹配。

在环境的代理设置中填写：

| 设置项 | 应填写的内容 |
|---|---|
| 代理类型 | HTTPS，与 VPS 入口实际协议一致 |
| 主机 | 本人的美国 VPS 入口地址或匹配证书的域名 |
| 端口 | 该 VPS 的 HTTPS 代理入口端口 |
| 代理用户名、密码 | 该入口生成的专用认证 |
| IP 刷新链接 | 固定住宅方案留空 |
| 使用系统代理连接代理 | 关闭，本方案由浏览器直接连接 VPS |

不要填本机回环地址，不要选“本地直连”，不要填 VPS 管理面板的网址，也不要直接粘贴 ClashFX 节点链接。浏览器需要访问 HTTPS 网站，不代表任何 HTTP 代理入口都能选择为 HTTPS；代理类型必须与入口协议匹配。[官方代理字段说明](https://help.adspower.com/docs/proxy_types)

保存设置并执行“检测代理”。通过后继续打开真实浏览器做下一步，不能到此结束。

### 第五步 设置和核对时区

浏览器时区设为“基于 IP”，核对识别的是实际住宅出口；自动识别错误时，按已核实的地区时区修正。语言可以使用基于 IP 的设置，定位权限保留询问，不默认给网站开放定位权限。其他指纹参数沿用合理默认值，环境建立后保持稳定。[官方指纹参数说明](https://github.com/AdsPower/adspower-browser/blob/main/skills/adspower-browser/references/fingerprint-config.md)

按本教程的要求，记录电脑原时区，再将系统时区设为住宅出口对应的地区时区。美国有多个时区，不能按 VPS 地区或“美国”两个字猜测。关闭基于电脑当前位置的自动时区，保留自动对时和该地区的夏令时规则。重新读取系统设置确认生效，并记录恢复方法。需要管理员验证时由本人处理。

按实际用途检查 WebRTC 设置；不用音视频功能时可以禁用，需要时选用当前版本支持的代理模式，并验证实际行为。不要把 IP 检测页正确，等同于所有浏览器连接都已验证。

### 第六步 在真实浏览器中验收

逐项执行并记录结果：

1. 打开刚配置的 AdsPower 环境，在该窗口访问 [Cloudflare 连接信息页](https://www.cloudflare.com/cdn-cgi/trace)，核对出口与本人购买的住宅出口一致。可另用一个独立查询服务复核。
2. 在同一窗口读取浏览器实际时区，例如运行 `Intl.DateTimeFormat().resolvedOptions().timeZone`，确认与核实的住宅地区一致。
3. 暂时关闭 ClashFX 的系统代理和增强模式，再用该窗口发起新的网页请求，确认仍可通过 VPS 使用同一住宅出口；测试后恢复原设置。若存在其他本地代理，也要核对是否仍有依赖。
4. 关闭并重新打开这个环境，确认代理与时区设置仍然生效。
5. 在该窗口检查 DNS、WebRTC 和公开 IPv6 的实际表现。发现绕过代理的公网连接时，处理并复测；暂时无法验证的项目明确写入待处理项。
6. 在保留原设置的前提下，仅将这个环境的代理端口暂时改为已确认未监听的端口，用新请求验证连接失败、未回退直连，然后恢复并复测。不要停止共用的主线服务。
7. 打开本人要使用的网站，检查页面能否正常加载。账号登录由本人操作；页面可达与账号登录成功分别记录。

公开进度只写“出口一致”“时区一致”“独立使用通过”等结果，不附实际 IP、认证资料、登录页面截图或含秘密的原始日志。详细连接资料和故障日志保存在本人独立私有位置。

### 第七步 给本人留下使用说明

告诉本人：以后打开 AdsPower，启动“美国住宅日常使用”环境即可；该环境按本方案直接连接 VPS。VPS 或住宅产品到期、来源白名单变化、证书失效，都可能导致无法连接。

交付环境名称、已完成项、待处理项和恢复原设置的方法。完成配置不代表任何平台账号一定获准使用。

## 遇到问题时让 Codex 按这个顺序检查

| 问题 | 先检查什么 |
|---|---|
| 检测代理失败 | VPS 是否可达、入口协议和端口、专用认证、访问限制、证书 |
| 检测通过但网页打不开 | 真实浏览器请求、VPS 出站、住宅网关、DNS 和 TLS 错误 |
| 关闭 ClashFX 后不能用 | 是否仍启用系统代理连接、VPS 接入是否被其他本地代理接管 |
| 出口不是预期住宅 IP | 环境代理字段、VPS 入站到住宅出站的路由、是否发生直连 |
| 换宽带后不能连接 | VPS 来源白名单、电脑到 VPS 的连接条件 |
| 时区不一致 | 住宅出口的地区识别、浏览器自动时区、系统自动时区是否覆盖手动设置 |

让 Codex 从《AdsPower配置进度.md》继续处理，不重复购买、重装或删除环境。说明当前错误后修正相应设置，不通过反复更换账号或指纹来测试网络。
